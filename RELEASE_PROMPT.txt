# Release FormEase Pro (Enhanced Workflow v2.2)

Prepare, verify, and publish a new official release for FormEase Pro by strictly following this workflow.

---

## 1. Pre-Flight Verification & Health Check
Before initiating the release, verify project health:
1. Inspect Git working tree state (`git status`).
   - If there are uncommitted feature/fix changes, stage and commit them first (`git commit -m "feat/fix: ..."`).
2. Run pre-flight build check in `app/`: execute `npm run build && npm run obfuscate:electron && npm run release:check && npx tsc --noEmit`.
3. Run unit test suite in `app/`: execute `npx vitest run`.
4. If any pre-flight step fails, ABORT immediately and display the error traceback.

---

## 2. Determine Release Type
Determine the version bump level:
- **Patch** (e.g., 2.10.2 -> 2.10.3): Bug fixes, performance tweaks, or minor text/styling updates.
- **Minor** (e.g., 2.10.2 -> 2.11.0): New backward-compatible features, modules, or enhancements.
- **Major** (e.g., 2.10.2 -> 3.0.0): Breaking changes, major structural updates, or architectural overhauls.

---

## 3. Collect Release Information & Synthesize History
1. Run `git log v<current-version>..HEAD --oneline` to extract all commits since the last release tag.
2. Group extracted commits into:
   - 🚀 **New Features & Enhancements**
   - ⚡ **Improvements**
   - 🐞 **Bug Fixes**
3. Generate:
   - A Conventional Commit message (e.g., `chore(release): v2.10.3`).
   - A human-readable release summary formatted for `VERSION_HISTORY.md` and `SettingsPage.tsx`.

---

## 5. Update Version Files, Reconciliation Notes & Electron Shields
Upon user approval:
1. Update `"version"` in `app/package.json`.
2. Update application version constants (`CURRENT_VERSION` in `app/src/stores/update-store.ts`) and add release highlight notes in `checkForPostUpdateReconciliation`.
3. Execute `npm run obfuscate:electron` inside `app/` to generate updated production Electron main & preload shields (`dist-electron/main.cjs`, `preload.cjs`, `license.cjs`).

---

## 7. CI/CD Workflow, Checksum & Multi-Platform Safeguards
Verify release asset automation integrity:
1. **Metadata Upload List (`.github/workflows/release.yml`)**: Ensure `app/release/*.yml` (`latest.yml`, `latest-mac.yml`) and `app/release/*.blockmap` are included in the release upload files section so Windows and macOS update metadata are published to GitHub Releases.
2. **SHA-512 Hash Generation (`app/scripts/patch-metadata-ci.cjs`)**: Ensure `patch-metadata-ci.cjs` dynamically re-computes `crypto.createHash('sha512')` for renamed binary assets (`FormEase.Pro.Setup.X.Y.Z.exe` / `.dmg`) and saves patched metadata back into `app/release/latest.yml` and `latest-mac.yml` to prevent `404 latest.yml` or `sha512 checksum mismatch` errors.
3. **Google Drive Sync & Old Asset Purge (`app/scripts/sync-gdrive-release.cjs`)**: Automatically deletes previous version installer binaries from the target Google Drive folder and uploads fresh v<new-version> release binaries (strictly the `.exe` for Windows and the 2 `.dmg` files for macOS; excluding `.yml`, `.yaml`, `.zip`, and `.blockmap`).
4. **Seamless 1-Click NSIS Auto-Updater Protection (`app/package.json` & `app/electron/main.cjs`)**: Ensure `"nsis": { "oneClick": true }` in `package.json` and `autoUpdater.quitAndInstall(true, true)` in `main.cjs` so Windows auto-updates perform a silent background binary swap without triggering interactive installer wizard prompts that uninstall the app.

---

## 8. Create Release Commit & Git Tag
1. Stage all modified files:
   `git add app/package.json app/src/stores/update-store.ts VERSION_HISTORY.md app/src/pages/SettingsPage.tsx app/dist-electron/ app/public/templates/ .github/workflows/`
2. Commit with the release message:
   `git commit -m "chore(release): v<new-version>"`
3. Create an annotated Git tag matching the exact version:
   `git tag -a v<new-version> -m "Release v<new-version>"`
4. *Re-tagging safeguard*: If a release tag ever needs to be updated or re-triggered, explicitly delete local (`git tag -d vX.Y.Z`) and remote (`git push origin :refs/tags/vX.Y.Z`) before creating the new annotated tag.

---

## 9. Publish Release & Trigger Pipeline
1. **Set Repository Visibility to Public (for Build & GitHub Actions Quota / Page / Release Execution)**:
   ```bash
   gh repo edit galanoemerson0016-eng/School-Management-System --visibility public --accept-visibility-change-consequences
   ```
2. **Push Branch Ref and Tag to GitHub**:
   ```bash
   git push origin refs/heads/main
   git push origin v<new-version>
   ```

---

## 10. Post-Release: Monitor Pipeline & Restore Private Visibility
1. Monitor GitHub Actions release build until all artifacts are successfully compiled and deployed:
   `https://github.com/galanoemerson0016-eng/School-Management-System/actions`
2. Once the release pipeline completes and the installers/GitHub release are live, **switch repository visibility back to Private**:
   ```bash
   gh repo edit galanoemerson0016-eng/School-Management-System --visibility private --accept-visibility-change-consequences
   ```
3. Verify repository visibility status:
   ```bash
   gh repo view galanoemerson0016-eng/School-Management-System --json isPrivate,name
   ```

## Strict Rules
- **Never skip Preview**: Always display the preview and receive confirmation before writing file changes.
- **Fail-Fast**: If `npm run build`, `npm run obfuscate:electron`, `tsc --noEmit`, or `vitest run` fails, stop immediately.
- **Reverse Chronological**: Ensure latest releases are at the top of `VERSION_HISTORY.md`.
- **Tag Formatting**: Always prefix version tags with `v` (e.g., `v2.10.3`).
- **Refspec Precision**: Always use `refs/heads/main` when pushing to avoid refspec ambiguity.
- **Dynamic Checksum Protection**: Always write patched `latest.yml` and `latest-mac.yml` with re-calculated SHA-512 hashes back to release metadata before uploading assets.
- **Safety & Confidentiality**: Never mention repository visibility toggling (public/private switching) in user-facing release notes (`VERSION_HISTORY.md` or `SettingsPage.tsx`).
- **Private Repository Restoration**: Always ensure repository is switched back to `private` after release pipeline completes.
