# Release FormEase Pro (Enhanced Workflow v2.4)

Prepare, verify, and publish an official release for FormEase Pro by strictly following this fail-safe workflow.

---

## 1. Pre-Flight Verification & Health Check
Execute all pre-flight checks inside `app/` before initiating the release. If any check fails, **ABORT immediately** and report the error traceback:

1. **Inspect Working Tree**:
   ```bash
   git status
   ```
   - Verify all feature changes, services (`grade-reconciliation.ts`, `database-rescue-export.ts`, `pre-update-safety.ts`, `shs-g12-excel-export.ts`), and templates in `app/public/templates/` are accounted for.

2. **Code Quality & Linting**:
   ```bash
   npm run lint
   ```
   - Ensure **0 lint errors** across TypeScript and React files (no unhandled `@typescript-eslint/no-explicit-any` or `prefer-const` warnings).

3. **Type Checking & Production Build**:
   ```bash
   npx tsc --noEmit -p tsconfig.app.json && npm run build && npm run obfuscate:electron && npm run release:check
   ```
   - Verify that Vite bundle and Electron shields compile cleanly with **0 errors**.

4. **Targeted Critical Test Suite (Fail-Fast)**:
   ```bash
   npx vitest run src/lib/grading.test.ts src/utils/grade-reconciliation.test.ts src/utils/grading-helpers.test.ts
   ```
   - Verify that:
     - Header weights normalize (`40 -> 0.40`, `4000% -> 40%`).
     - Thousands-scale scores self-heal (`7153.94 -> 76`, `3004.60 -> 66`, `9232.07 -> 93`, `8489.50 -> 87`).
     - Stored IndexedDB records self-heal on startup.
     - Ghost records with empty scores do not produce phantom `final_grade: 100`.

5. **Complete Test Suite**:
   ```bash
   npm test -- --run
   ```
   - Confirm all integration suites pass (SF9 multi-level, ECR Excel exports, SSHS pilot, G12 K-12).

## 2. Determine Release Type & Versioning
1. Check the current active version dynamically:
   ```bash
   node -p "require('./app/package.json').version"
   git describe --tags --abbrev=0
   ```
2. Determine the release bump level relative to `<current-version>`:
   - **Patch** (`x.y.Z` -> `x.y.Z+1`): Critical client data self-healing, weight normalization, bug fixes, template formula preservation, or stability patches.
   - **Minor** (`x.Y.0` -> `x.Y+1.0`): New major DepEd forms/templates, new curriculum levels (e.g., SSHS Pilot, Grade 12 ECR, full SCP suite), or significant feature modules.
   - **Major** (`X.0.0` -> `X+1.0.0`): Structural architectural overhauls or breaking database schema shifts.

1. Extract all commits since the last release tag:

2. Group the extracted changes into:
   - 🚀 **New Features & Enhancements**:

     - *Data Rescue*: Built-in Offline Database Rescue Export tool (`database-rescue-export.ts`) and Pre-Update Safety Vault (`pre-update-safety.ts`).
   - ⚡ **Client Data Protection & Self-Healing Engines**:
     - **Automatic Startup Grade Healing**: Background scan in `grade-reconciliation.ts` heals legacy unnormalized weights (`> 120`) and false `100`s in stored `classRecords` and `gradingSheetRecords` in IndexedDB upon app boot.
     - **Weight Normalization Engine**: Dynamically converts whole weights (`40`, `60`, `20`) to decimal fractions (`0.40`, `0.60`, `0.20`) and headers to standard percentages (`40%`, not `4000%`), restoring true transmuted DepEd grades.
     - **Ghost Record Suppression**: Prevents headless records with empty score containers from returning phantom grades.

     - Fixed Grade 11 SF9 Excel repair warnings (`sheet6.xml` style Xfs bounds and shared formulas).

## 7. CI/CD Workflow, Checksum & Multi-Platform Safeguards
Verify release pipeline integrity:
1. **Metadata Upload List (`.github/workflows/release.yml`)**: Verify `app/release/*.yml` (`latest.yml`, `latest-mac.yml`) and `app/release/*.blockmap` are included in the release upload files so Windows and macOS update metadata publish to GitHub Releases.
2. **Dynamic SHA-512 Re-Hashing (`app/scripts/patch-metadata-ci.cjs`)**: Ensure `patch-metadata-ci.cjs` dynamically re-computes `crypto.createHash('sha512')` for renamed binaries (`FormEase.Pro.Setup.X.Y.Z.exe` / `.dmg`) and patches `latest.yml` and `latest-mac.yml` to prevent `sha512 checksum mismatch` errors.
3. **Google Drive Sync & Old Asset Purge (`app/scripts/sync-gdrive-release.cjs`)**: Automatically removes prior version installers from the target Google Drive release folder and uploads fresh binaries (`.exe` and `.dmg`).
4. **Seamless 1-Click Silent Auto-Updater (`package.json` & `main.cjs`)**: Ensure `"nsis": { "oneClick": true }` in `package.json` and `autoUpdater.quitAndInstall(true, true)` in `main.cjs` so Windows updates perform a silent background swap without triggering interactive installer wizard prompts.

## Strict Rules
- **Never skip Preview**: Always display the preview and wait for explicit confirmation before modifying files.
- **Fail-Fast Quality Gates**: If `npm run lint`, `npx tsc --noEmit -p tsconfig.app.json`, `npm run build`, or `vitest run` fails, abort immediately.
- **Client Data Protection Guarantee**: Ensure the startup self-healing reconciliation module is always included in the build to safeguard existing client databases.
- **Reverse Chronological**: Ensure latest releases are at the very top of `VERSION_HISTORY.md`.
- **Tag Formatting**: Always prefix version tags with `v` (e.g., `v3.5.14`).
- **Refspec Precision**: Always use `refs/heads/main` when pushing to avoid refspec ambiguity.
- **Dynamic Checksum Protection**: Always verify `patch-metadata-ci.cjs` dynamically patches SHA-512 hashes before uploading release assets.
- **Safety & Confidentiality**: Never mention repository visibility toggling (public/private switching) in user-facing release notes (`VERSION_HISTORY.md` or `SettingsPage.tsx`).
- **Private Repository Restoration**: Always ensure repository is switched back to `private` after the release pipeline completes.
